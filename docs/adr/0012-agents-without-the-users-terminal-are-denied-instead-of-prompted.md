# Agents without the user's terminal are denied what their rules do not allow, instead of prompted

Spec 03 rule 12 keeps the provider's native permission prompts. In M1 only Coordination's terminal takes the user's keys, in the conversation: `asmai attach` only observes, so a native prompt in any other agent's terminal waits for an answer nobody can give, and its job stalls in silence. Claude Code 2.1.292 raises one for more than the write guard's refusals: it cannot judge a shell command with a brace next to a quote character ("Contains brace with quote character (expansion obfuscation)"), such as a heredoc that writes `import { test } from 'node:test'`, so it asks before running it whatever the sandbox's auto-allow and AsmAI's allow rules say; and in the default mode it asks before every Edit and Write a rule does not allow. So no agent without a user terminal may ever wait at a native prompt. Every agent but Coordination's leader, the Engineering and Quality leaders and every worker, runs in Claude Code's `dontAsk` permission mode: anything its rules do not allow is denied, with no prompt and no approval given, and the agent is told so, uses an allowed route, or reports itself blocked (`asmai blocked` for a worker, through Coordination for a leader). A worker's rules allow its Edit and Write tools in its own workspace and temporary directory, by the paths the session sees and the paths they resolve to, and workers are told to write files with those tools, never with shell heredocs or `cat > file`: a heredoc or compound command the shell analyser marks too complex, such as one with a brace next to a quote character, is denied in `dontAsk` mode, and a plain one may run in the sandbox. Coordination's leader stays in the `default` mode, and keeps rule 12's native prompts, which the user answers in the conversation. This amends how rule 12 applies: for an agent with no user terminal, the provider's native prompt becomes the provider's denial.

## Considered Options

- **`dontAsk` for every agent without the user's terminal, scoped Edit rules for workers, and the daemon reporting any prompt that still comes up** (chosen).
- **Keep `default` and only tell workers to use the Write tool**: each Edit and Write a rule does not allow still asks, and any other unforeseen prompt still stalls the job.
- **`acceptEdits` for workers**: no edit prompts, but it also accepts edits outside the workspace, and every other prompt still stalls.
- **Auto mode**: a model classifier answers the prompts instead of the user. That is an approval no human gave, which rule 10 forbids; it depends on the account supporting it, and managed settings can switch it off, so qualification results would differ by account.
- **Answer prompts in the other agents' terminals**: that is the planned interventions work, not M1.

## Consequences

- `dontAsk` grants nothing the rules did not already allow: it only turns would-be prompts into denials, so no approval is ever given without the user. A legitimate action the rules do not foresee, such as a network host the write guard does not allow, now fails instead of waiting; the agent reports it, and the user changes the rules or does it.
- A worker's Edit and Write tools change files in its workspace and temporary directory without a prompt. The write guard already let its shell commands write there.
- The daemon still journals every `PermissionRequest`. One from any agent but Coordination's leader means a prompt nobody can answer: `asmai status` lists it and every attach client's status line shows it, as "worker1@engineering waits at a native prompt nobody can answer", until the session reports another event.
- The behaviour is the pinned Claude Code's. Qualification case C49 proves it for each pin: a worker writes a JavaScript test with braces and quotes with the Write tool with no prompt, and the same content through the shell heredoc compound the #36 demo's worker stalled at (`mkdir -p test && cat > test/index.test.js <<'EOF'` … `EOF` then `npm test 2>&1 | tail -12`) is denied in `dontAsk` mode, the session told so, and reports itself blocked. C37 now requires the write guard's refusals that a retry outside the sandbox would have prompted for to be denied in `dontAsk` mode.

Decided on 2026-10-14 in [issue #77](https://github.com/talvor/asmai/issues/77), from the diagnosis of the #36 demo at 397c648.
