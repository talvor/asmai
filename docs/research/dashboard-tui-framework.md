# Research: TUI framework vs hand-rolled for `asmai dashboard`

Ticket: talvor/asmai#102 (part of map #100). Researched 2026-10-15 against the repo at `main` (95e608c) and the primary sources named inline.

## Question

Which approach fits this repo for the dashboard: a framework (Bubble Tea with Lip Gloss) or hand-rolled on `golang.org/x/term` and `internal/vt`? For each: licence and notice obligations, how pins are handled, size and maintenance, and whether it composes with suspending for `asmai attach` and the raw-terminal handling the attach client already does.

## Short answer

Both are admissible. A framework is feasible without touching the licence policy; the real costs are a larger dependency graph (about a dozen new modules, one an untagged pseudo-version) and a second owner of raw-terminal state beside the attach client's. Hand-rolling is feasible because the repo already owns a renderer and raw-mode handling, but the dashboard needs a widget layer (layout, scrolling, key decoding, filtering) that `internal/vt` does not provide. The hand-over to `asmai attach` composes with both: with Bubble Tea it goes through `tea.ExecProcess`; hand-rolled it is a small `term.Restore` / `term.MakeRaw` routine of the shape `attach.go` already uses.

## What the repo has today

- Direct dependencies in `go.mod`: `creack/pty`, `google/licensecheck`, `ncruces/go-sqlite3`, `pelletier/go-toml/v2`, `golang.org/x/sys`, `golang.org/x/term`. Go 1.26.7. (`go.mod`)
- `internal/vt` is "AsmAI's own terminal emulation" (about 1.7k lines across `parse.go`, `render.go`, `screen.go`, `vt.go`, `width.go`, tests). It is a screen model plus a `Renderer` (`Render(t, columns, rows) []byte`, `Invalidate()`), built to replay an agent's screen, not to lay out application widgets. (`internal/vt/vt.go`, `render.go`)
- `cmd/asmai/attach.go` already does the raw-terminal work with `x/term` directly: `term.IsTerminal`, `term.GetSize`, `term.MakeRaw` then `term.Restore` on exit, `signal.Notify(SIGWINCH)` for resizes, and a key reader goroutine. (`show`, `followSize`, `readKeys`)
- ADR 0004: the attach client draws the status line itself, one row under the agent's screen. ADR 0001: the daemon owns terminals. The dashboard is read-only and hands over to `asmai attach` (map #100, "Settled up front").

## Licence and notice obligations

Policy (`CONTRIBUTING.md`, `internal/licenses/licenses.go`): every Go module compiled in must be MIT, BSD-2, BSD-3, Apache-2.0 or ISC (`Allowed`); CI checks this with `check-licenses`; `THIRD_PARTY_NOTICES` is generated by `make notices` (`internal/cmd/gen-notices`), embedded via `legal.go`, printed by `asmai notices`, and CI fails on drift. Widening the list is the maintainer's decision.

Hand-rolled on `x/term`: no new module, no change to `THIRD_PARTY_NOTICES`.

Bubble Tea v2 (`charm.land/bubbletea/v2@v2.1.0`, published 2026-10-08 per the Go module proxy) and Lip Gloss v2 (`charm.land/lipgloss/v2@v2.0.6`, 2026-08-11):

- Bubble Tea's LICENSE is MIT (Charmbracelet, Inc.), read from the module zip. Lip Gloss is also Charmbracelet.
- Their `go.mod` files require: `charmbracelet/colorprofile`, `charmbracelet/ultraviolet`, `charmbracelet/x/ansi`, `charmbracelet/x/term`, `charmbracelet/x/termios`, `charmbracelet/x/windows`, `lucasb-eyer/go-colorful`, `muesli/cancelreader`, `clipperhouse/displaywidth`, `clipperhouse/uax29/v2`, `mattn/go-runewidth`, `rivo/uniseg`, `xo/terminfo`, `aymanbagabas/go-udiff`, `golang.org/x/exp`, `golang.org/x/sync`, `golang.org/x/sys`.
- LICENSE files checked in the module zips: MIT for ultraviolet, x/ansi, colorprofile, cancelreader, go-colorful, x/term, displaywidth, terminfo, uniseg, go-runewidth; go-udiff is BSD-3-Clause style (Go Authors text). `x/termios`, `x/windows`, `uax29`, `x/exp` and `x/sync` were not individually opened. All are expected to be on the allow-list, but `go run ./internal/cmd/check-licenses` is the authority and must be run when adopting.
- Obligation: MIT and BSD require the copyright and licence text to accompany binary distributions. The repo's existing mechanism covers that: run `make notices` and commit. Windows-only modules are not compiled for the two certified platforms (linux-x64, darwin-arm64 in `pins.json`), and the notices cover modules compiled for Linux x86_64 and macOS on Apple silicon, so they should not appear.
- No licence-policy change is needed, which matters because widening the allow-list is reserved to the maintainer.

## How pins are handled here

- `pins.json` pins provider CLIs only (currently `claude-code` 2.1.292 with per-platform SHA-256 and size). It is not a Go dependency pin; a TUI library does not go there. (`pins.json`, `pins.go`)
- Go dependencies are pinned by `go.mod` / `go.sum`, and the Go version by `go.mod`. A framework would be pinned the same way, at an exact version. No `vendor/` directory exists, so no vendoring policy changes.
- Wrinkle: Bubble Tea v2.1.0 requires `charmbracelet/ultraviolet v0.0.0-20261008173134-6b8d4baf91b4`, an untagged pseudo-version. It is still hash-pinned by `go.sum`, but a bump follows upstream commits rather than release tags.

## Size and maintenance

- Bubble Tea v2.1.0's root package is about 6.6k lines of Go including tests (module zip). With its dependency set, the compiled addition is considerably larger than `internal/vt`. Binary growth was not measured here; measure it with `make build` before and after in the implementation slice.
- Maintenance: the v2 line is recent (module path moved to `charm.land/...`, `UPGRADE_GUIDE_V2.md` ships in the repo), with pseudo-versioned components in the chain. Adopting means tracking upstream bumps and re-running `make notices` for each. That sits against the repo's qualification posture (ADR 0008, 0009): the dashboard's terminal behaviour would need re-qualifying on a bump.
- Hand-rolled: a bounded set of code the repo owns and tests: a list/detail layout, scrolling, key decoding (arrows, escapes), a filter prompt, resize handling, a redraw loop. `internal/vt.Renderer` already diffs a cell screen to minimal output and handles character width (`width.go`), and could serve as a back buffer, though it was designed for faithful playback of another program, so this is an adaptation. Key decoding is the part with no existing code: `attach.go`'s `readKeys` forwards bytes and watches only for the Ctrl-] menu.

## Composition with suspending for `asmai attach` and raw-terminal handling

ADR 0001 and the map put attach as a hand-over: the dashboard stops drawing, gives the terminal to `asmai attach`, then resumes.

- Bubble Tea v2: `tea.ExecProcess(*exec.Cmd, callback)` "effectively pausing the Program while the command is running and resuming it when execution has completed" (`exec.go`). Underneath, `Program.ReleaseTerminal()` cancels the input reader, stops the renderer and restores terminal state, and `RestoreTerminal()` re-initialises terminal, input and renderer, repaints, and re-checks size (`tea.go`). Running `asmai attach <agent>` as a child process therefore composes: the attach client's own `term.MakeRaw`/`Restore` runs on a terminal Bubble Tea has released, and resizes during the child are re-detected on resume. Ctrl-Z goes through `SuspendMsg`/`ResumeMsg`.
- Child process, not in-process: for either approach, running the attach client in-process inside the dashboard would give two stdin readers and two SIGWINCH listeners. Re-executing the single executable as `asmai attach` keeps ADR 0004's status line unchanged.
- Hand-rolled: the dashboard owns one `term.MakeRaw` state. Hand-over is: stop the key reader, `term.Restore`, leave any alternate screen, run the child, then `MakeRaw`, re-enter, re-measure with `GetSize`, and `Invalidate()` the renderer. This is the code shape `show()` in `attach.go` already has and could be shared with it. The hazard is stopping a blocking read on stdin; Bubble Tea solves it with `muesli/cancelreader`, a module the repo would otherwise not need.
- SSH: Bubble Tea v2 queries terminal capabilities and colour profile (`colorprofile`, `termcap.go`), extra terminal traffic that must behave over SSH and tmux; hand-rolled emits only what it needs. This is a qualification item either way, not a differentiator the sources settle.

## Trade-offs

| Concern | Framework (Bubble Tea v2 + Lip Gloss v2) | Hand-rolled (`x/term` + `internal/vt`) |
|---|---|---|
| Licence | MIT/BSD chain, within allow-list (verify with `check-licenses`) | none new |
| Notices | `make notices` adds about a dozen modules | unchanged |
| Pins | `go.mod`/`go.sum`; one untagged pseudo-version (ultraviolet) | none |
| Code to own | model/update/view for the dashboard | plus layout, scroll, key decode, filter, redraw loop |
| Hand-over to attach | `tea.ExecProcess`, built in | small restore/make-raw routine, patterned on `attach.go` |
| Qualification surface | upstream renderer and input changes per bump | repo-owned, changes only with the repo |
| Fit with repo style | new idiom (Elm-style messages) | same idiom as `attach.go` and `internal/vt` |

## Open items for the decision (not decided here)

1. Whether the dashboard's complexity (list, detail pane, filter by job or agent, log toggle) justifies a widget layer; this depends on the spec under #100.
2. Whether the maintainer accepts an untagged pseudo-versioned dependency and re-qualification per bump.
3. Measured binary size delta, and a spike confirming `ExecProcess` of `asmai attach` leaves the status line and resize behaviour intact on both certified platforms; not measured here.
4. Whether the framework choice warrants its own ADR (map #100, "Not yet specified").
